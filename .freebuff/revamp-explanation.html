Post-mortem · commit cb1fa56 “NEW AND IMRPROVED UI”

A 2,408-line redesign shipped completely dead. The fix was 14 file moves — not a rewrite.

The revamped interface was authored in one directory layout and committed in another. Every relative import pointed at a file that did not exist, so the bundle never linked and the new UI could never paint. Crucially, the broken paths still encoded the intended layout — which is what made the recovery exact rather than guesswork.

01The orphan island

Two complete applications lived in src/: the shipping one under pages/ + components/, and a whole new dark design system sitting loose at the top level. Nothing referenced the new system, so the bundler never walked it — it existed only as text on disk.

Why the bundler never complained

The revamp was not imported by any file the bundler could reach, so the module graph never traversed it. A build is perfectly happy with code it never sees — the files were syntactically fine, the design was fine, and the commit was green.

The trap worth calling out

cn.ts was the only definition of cn() in the entire repository, and it sat at src/cn.ts — a path nothing imported. Every one of the 11 files that used it was reaching for lib/cn, which did not exist.

That is also why a casual scan marks the file as dead code and deletes it. I did exactly that, caught it when the resolution script went red, and moved it to src/lib/cn.ts instead.

03The recovery: read intent off the broken paths

The instinct is to open 2,408 lines and rewrite the imports. That is unnecessary. A relative import is a precise statement about where a file lives. ../components/ui/BentoGrid from inside a pages/-level folder means the primitives belong one level below src/ in components/ui/. The paths were wrong as a set, but internally consistent — so moving files to satisfy them makes all 44 resolve at once, with no edit to a single line of the redesign.

Before — dead
1src/Landing.tsx
2imports "../components/ui/BentoGrid"
3src/ + ../components/ui/BentoGrid
4components/ui/BentoGrid — above src/. Does not exist.
After — resolves
1src/revamp/Landing.tsx
2imports "../components/ui/BentoGrid" — unchanged
3src/revamp/ + ../components/ui/BentoGrid
4src/components/ui/BentoGrid.tsx — found.

The same arithmetic for ../../lib/cn: a file two levels below src/ reaching for lib/cn lands on src/lib/cn.ts — the project’s real utilities folder. ../data/mock from a src/-level folder lands on src/data/mock.ts, beside the existing tracks. Four target directories, one consistent interpretation, zero rewritten imports.

Design decision: own route, own chunk

The revamp went to /revamp rather than over the existing / and /leaderboard. Both designs contain a Landing.tsx and a Leaderboard.tsx, so replacing the live routes is a migration with real product consequences — not a rename. Isolating it keeps that decision reversible and leaves the entry bundle untouched for existing visitors.

05The compatibility trap

The single most dangerous line in codexter.css was not broken — it was correct, and wrong for this codebase. Two design systems, each with its own opinion about the page background.

As authored — leaks
 body { background: #030305; color: #d4d4d8 }
→Global. Applies to every page in the app, not just the revamp.
→The warm light / page and all 15 dark lesson pages go black.
As shipped — scoped
 .codexter-dark { background: #030305 }
→Two-class selector; applies only inside the revamp root.
→Verified in the built CSS: 0 bare html/body selectors survive minification.
The second-order landmine: tests/palette.test.ts

This repo has a palette audit that recursively scans every .ts/.tsx file under src/ and requires that any paper-*, ink-* or gold-* token mentioned in source is declared as a CSS variable in :root and mirrored in .dark.

Adding 2,408 lines to src/ silently widened that audit’s blast radius. The escape hatch was luck: the revamp’s palette is entirely default Tailwind shades plus hex (cyan-300, violet-600, #030305) and mentions paper/ink/gold zero times. Had it used one new ink-150, the suite would have failed for a file that looks perfectly correct in isolation.

Regression check that mattered

After scoping, the old landing page was re-inspected at runtime: no .codexter-dark element present, its <h1> still computing to Fraunces, Georgia, serif, body background still the app’s own rgb(14,14,16) — not the revamp’s #030305. Two palettes, coexisting.

07Limits and honest caveats

Not fixed, and not mine to fix silently

npm test is red on main because of the 3 pre-existing debug-challenges timeouts. I left them alone: raising the timeout would mask the question rather than answer it. Whether they are genuinely slow or genuinely hanging is still open, and worth settling before the revamp builds on top of the suite.

  • In-app screenshots were unavailable. The preview webview would not composite, so preview_screenshot returned “produced no frames” throughout. I captured with headless Chrome and verified pixels by decoding the PNGs in Node (zlib only, no new dependencies).
  • Self-inflicted outage, resolved. I briefly placed Chrome’s profile directory inside the repo root; Vite’s watcher hit a locked Cookies file and crashed the dev server. Cleaned up, restarted, and moved profiles to %TEMP%.
  • One judgement call worth surfacing. src/cn.ts appeared to be dead code and I deleted it before the resolution script proved otherwise. It was the repo’s only cn(). Caught and placed at src/lib/cn.ts. A static “unused export” scan would have made the same mistake.
  • Coverage is viewport-only. Screenshots are 1440×900 top folds, not full-page. Responsiveness and dark-mode interaction in the revamp are not verified here.
  • The revamp is not adopted. It is reachable and correct at /revamp, but no existing route points at it. Wiring it over / and /leaderboard remains an open product decision.
